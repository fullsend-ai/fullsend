ADR 0091 · playground matrix · 2026-08-21

Always-on skills beat Quay-style listing

Nine successful triage runs on fullsend-playground/python-app (3 arms × 3 reps) with a fixture that forces labeling. With Skill in triage tools:, default forge/label skills open reliably. An additive team skill opens only when marked metadata.apply: always (Option B). Listing it on the harness alone (Quay-style) never opened it in 3/3 runs.

ADR 0091 takeaway: name skills in the agent prompt or mark them always-on. Harness listing alone is not enough.

What we measured

  • Skill tool present — init tools includes Skill (requires spaced frontmatter Bash(...), Skill).
  • issue-labels path — Skill body # Issue Labels / “Discover available labels” loaded (uploaded as skill name github from skills/issue-labels/github).
  • Additive skill — Skill tool_use for smoke-listed or smoke-always-on.
  • Behavior — triage comment starts with exact token CAVEMAN:.

Fixture: unique PATCH /items silent-drop bugs (API + high impact) so labeling is warranted and duplicates are avoided. Retro insight: retro.md names skills in the prompt body (like retro-analysis) — that pattern matches why forge/label skills fire once Skill exists.

How ADR 0091 should work

  1. Prerequisite: agent tools: must include Skill with a space after the comma (Bash(gh,curl,jq), Skill). Without the space, Claude boots as ["Bash"] only — see agents#928.
  2. Default / named skills (issue-labels via forge path, retro’s named skills): open reliably once Skill exists — same as historical pre-Jul-6 triage.
  3. Team additive skills (Quay-style harness list only): uploaded and visible, but not opened (0/3). Matches the ADR problem statement.
  4. Always-on (metadata.apply: always + __FULLSEND_ALWAYS_ON_SKILLS__ fill): additive skill opened 3/3 and changed behavior (CAVEMAN comments).
